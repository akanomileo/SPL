# SPL Connected Shop v3.2

Both customer and owner login/signup use Google only. Customer / opens a dedicated welcome/login page; the shop loads after successful Google sign-in. First sign-in registers a new Google account automatically. Existing Google accounts are reused. Password login/registration/linking endpoints are disabled, and legacy password sessions are rejected. Authenticated catalogue access is enforced by the backend.

The owner is no longer tied to a fixed email allowlist. A private server-console command issues a one-time code; the first authorized Google selection binds one stable Google account ID. Database/transaction checks prevent two setup callbacks from creating two owners. Normal owner login uses only Google. An explicit private replacement command revokes former owner sessions and allows one new owner, preserving orders/products. Customer navigation contains no owner link.

Existing Google accounts/orders survive upgrade. Legacy customer password accounts require an administrator to authorize their migration before Google attaches to them. A Google-verified owner setup can claim an older account with the same email because the private setup code authorizes that choice. No normal customer email is silently merged, and migration does not grant owner privileges.

Validation includes 27 automated tests: signed Google identity verification, invalid issuer/audience/expiry/nonce/signature rejection, browser-bound and single-use OAuth state, PKCE, private/expired setup codes, competing owner setup callbacks, replacement/revocation, legacy migration, password endpoint/session rejection, stock/idempotency/order isolation and persistence. TypeScript, lint, production build and browser login/ordering/dashboard checks are part of release verification. Google provider interactions are mocked because no real OAuth client credentials were supplied. See GOOGLE-SETUP.md to activate and verify real Google login.

The ZIP includes full source and the prebuilt frontend, with no node_modules, database, private uploads, Google credentials, owner identity or setup code. Requires Node.js 22.13+. Production needs HTTPS, a Node host, persistent private storage/backups and the real Google OAuth client configuration. No actual domain/deployment was tested. Payments are arranged separately; no online payment processing or email/SMS notifications are included. Views show the most recent 200 orders. Google uses identity permissions only, with no Gmail mailbox access or stored Google access/refresh tokens.

Product photos, prices, stock, warranty and contact details originate from uploaded files and need owner confirmation. Prior dependency review reported 9 findings (0 critical, 6 high, 3 moderate) in inherited framework/build chains. The standalone backend uses Node builtin modules; upstream dependency patches still need review. Validation is not a complete security, accessibility or all-browser audit. Main is preserved; downloadable releases are on the authorized delivery branch.
